## 3. Packaging audit (acceptance 5)

`package.json` and `cordis.patch.yml` were audited field by field for a profile install; the only changes
made were `description`, `keywords` and two `files[]` entries.

| field | value | why it is correct |
|---|---|---|
| `main` | `lib/index.js` | the DSH host Loader imports the package entry; the file exists after `pnpm build` |
| `exports["."]` | `./lib/index.js` | same host entry |
| `exports["./client"]` | `./lib/client.js` | `dsh-client-modules` requires `exports["./client"]` to exist for a package declaring `dsh.client` |
| `exports["./src/*"]`, `./package.json` | unchanged | source access for consumers; manifest self-reference |

| `dsh.bundle.patch` | `./cordis.patch.yml` | the bundle layer the profile applies |
| `cordis.patch.yml` | one `insert:` row `{id: subagent-view, name: 'subagent-view'}` | mounts the host half; semantics unchanged in `0.1.5-rc.2` (migration §2 H13 / change item 15); left untouched |
| `peerDependencies` | all `@deepseek-ai/*` at `>=0.1.5-rc.2`, `cordis >=0.1.0` | records the platform the bundle is built and verified against |
| `peerDependenciesMeta` | `@deepseek-ai/dsh-client-ui-sidebar-right` → `{optional: true}` | a profile that does not compose `ui-sidebar-right` must still install; the plugin then keeps surfaces 1–2 (verified R11.6) |
| `dependencies` | `react ^18.2.0` | `react` is served by the browser seed table (the client bundle `require`s it, and every DSH web page has it) |
| `devDependencies` | … , `zod ^4.4.3` | build-time only: tsdown inlines zod into `lib/index.js`, so the host half has **no** zod import at runtime — see §6 L5 and `docs/MIGRATION-0.1.5-rc.2.md` §7 R1. Moved here from `dependencies` by the 0.1.5 follow-up pass, which discharged R1/P0-2 |
| `files[]` | `lib/index.js`, `lib/client.js`, **`lib/index.js.map`**, **`lib/client.js.map`**, `cordis.patch.yml`, `src`, `README.md`, `LICENSE`, `docs` | everything a profile install reads |

**Why `files[]` is load-bearing (measured, not assumed).** A `file:` install is filtered by
`files[]` — it is a copy, not a whole-directory link. A probe in `.scratch/t6-install-probe` installed a
package declaring `files: ["index.js","docs","cordis.patch.yml"]` with `pnpm add file:…`; only
`index.js`, `docs/`, `cordis.patch.yml` and `package.json` landed, while `src/main.ts`, `lib/index.js`,
`.env.local`, `.gitignore` and `node_modules/` did not. A listed entry that does not exist is skipped
silently (exit 0), so declaring the two source maps is safe for an unbuilt tree and makes
`lib/client.js.map` available to `dsh-client-modules`, which serves `/plugins/<id>/client.js.map` when the
map file is present ("missing maps do not prevent plugin execution"). `pnpm pack` confirms the manifest:
the tarball contains `package.json`, `cordis.patch.yml`, `README.md`, `LICENSE`, `lib/{index,client}.js`
plus both maps, `src/` (6 files) and `docs/`.
